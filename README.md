# 선민종합관리 민원 처리부

관리사무소 민원을 **접수 → 지시 → 보고 → 회신** 순서로 처리하는 웹 앱입니다.
화면은 GitHub Pages(`https://airrotc29.github.io/minwon/`)에서 열리고, 데이터는 **Supabase 서버 데이터베이스**에 저장되어
같은 주소로 접속해 로그인한 모든 사람·기기가 같은 내용을 봅니다. 아래 「서버 설정」을 한 번 해 주세요.

## 사용 흐름

1. **접수 (관리소장 또는 직원)**: `+ 민원 접수`에서 동·호수, 분류, 긴급 여부, 내용을 입력합니다.
   - 직원이 접수하면 접수자 이름이 남고, 소장님 화면 **지시 대기**로 넘어갑니다.
   - 직원이 `내가 바로 처리`에 체크하면 소장 지시 없이 자기 담당으로 바로 처리하고 보고를 올립니다.
2. **지시 (관리소장)**: 담당 직원, 처리 기한, 지시 사항을 정해 보냅니다. 처리 중에는 `담당 변경 · 추가 지시`로 담당을 바꾸거나 지시를 더 보낼 수 있습니다.
3. **보고 (직원)**: 상단 `직원` 화면에서 자기 이름을 고르면 자기에게 온 지시만 보입니다. 여기서 `진행 보고`나 `완료 보고`를 올립니다.
4. **회신 (관리소장)**: 완료 보고가 오면 상단에 **회신 대기 N건**이 표시됩니다.
   - 민원인에게 보낼 안내 문구가 자동으로 만들어집니다. 휴대폰에서 노란 **카톡으로 보내기**를 누르면 공유창이 뜨고, 카카오톡에서 받을 방을 고르면 문구와 완료 사진이 함께 갑니다(문구는 복사도 되어 있어 글이 빠지면 붙여넣기). PC에서는 문구가 복사되니 PC 카톡에 붙여넣으면 됩니다.
   - 고친 뒤 `문구 복사`로 붙여 보내거나 인터폰·방문으로 알립니다.
   - 알린 방법(인터폰, 방문, 전화, 문자, 카톡, 안내문 부착)을 고르고 `회신완료로 기록`하면 **회신완료**로 바뀝니다.
   - 처리 중에도 `민원인에게 중간 안내`를 보낼 수 있고, 보고가 부족하면 `재작업 지시`로 다시 돌려보냅니다.

## 사진

- 접수할 때와 직원이 진행·완료 보고를 올릴 때 **＋ 사진**으로 사진을 붙입니다(한 번에 6장까지). 휴대폰에서는 바로 촬영하거나 앨범에서 고를 수 있습니다.
- 휴대폰 사진은 올리기 전에 자동으로 줄입니다(긴 변 1280px, 장당 약 150KB).
- 처리 내역에 작은 사진으로 보이고, 누르면 크게 보거나 저장할 수 있습니다.
- 사진은 Supabase의 비공개 사진 저장소(`photos`)에 저장되고, 로그인한 사람만 볼 수 있습니다.
- 백업 파일(json)에는 사진이 들어가지 않습니다.

### 사진 용량
Supabase 무료 요금제의 사진 저장 한도는 **1GB(약 6,800장)** 입니다.

| 하루 사진 수 | 무료 1GB로 버티는 기간 |
|---|---|
| 10장 | 약 1년 10개월 |
| 30장 | 약 7~8개월 |
| 50장 | 약 4~5개월 |

- `직원·설정 → 서버`에 사진 장수와 사용량(어림값)이 보이고, 80%를 넘으면 소장님 화면 위쪽에 안내가 뜹니다. 정확한 값은 Supabase 대시보드 → Storage에서 봅니다.
- 한도가 차면 **Pro 요금제(월 25달러)** 로 올리면 사진 저장이 100GB(하루 30장 기준 수십 년)로 늘고, 매일 자동 백업과 일시정지 없음이 함께 따라옵니다.

## 로고

- 저장소 루트에 `logo.png` 파일을 올리면 상단과 브라우저 탭에 선민종합관리 로고가 표시됩니다.
- 또는 앱의 `직원·설정 → 로고 이미지 올리기`로 그 기기에만 로고를 넣을 수 있습니다.
- 로고가 없으면 초록색 "선민" 글자 마크가 대신 보입니다.

## 서버 설정 (Supabase) — 처음 한 번

### 1. 가입하고 프로젝트 만들기
1. https://supabase.com 접속 → **Start your project** → **Continue with GitHub**(지금 GitHub 계정으로 가입).
2. **New project**
   - Organization: 처음 만들 때 이름 아무거나, 요금제 **Free**
   - Project name: `minwon`
   - Database Password: **Generate a password** 누르고 따로 적어 두기(앱에서는 안 씀)
   - Region: **Northeast Asia (Seoul)** — 데이터가 국내에 저장되도록(개인정보 국외 이전 문제 예방)
   - **Create new project** → 1~2분 기다리기

### 2. 데이터베이스 만들기 (복사·붙여넣기 한 번)
1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 저장소의 [`supabase/schema.sql`](supabase/schema.sql) 내용을 전부 복사해 붙여넣고 **Run**
3. 아래에 `Success. No rows returned`가 나오면 끝(민원·처리내역·직원·설정 표, 관리소장/직원 권한 규칙, 실시간 반영, 사진 저장소가 한 번에 만들어집니다)
   - "destructive operation" 경고가 뜨면 **Run query**. 표를 지우는 명령은 없어서 여러 번 실행해도 데이터는 그대로입니다.
   - 앱이 새 버전으로 바뀌면서 이 파일이 바뀌었을 때도 같은 방법으로 다시 실행하면 됩니다.

### 3. 로그인 계정 만들기
1. 왼쪽 **Authentication** → **Sign In / Providers**(또는 Providers) → **Email**이 켜져 있는지 확인
2. 같은 화면(또는 Authentication → Settings)에서 **Allow new users to sign up**을 **끄기** — 아무나 가입하지 못하게
3. **Authentication → Users → Add user → Create new user**
   - 소장님 계정: 이메일, 비밀번호 입력, **Auto Confirm User** 체크 → Create user
   - 직원 계정: 직원마다 하나씩(권장) 또는 공용 계정 하나. 직원 이메일이 없으면 `park@sunmin.kr`처럼 형식만 맞춰도 됩니다(메일은 발송되지 않음).

### 4. 앱에 서버 주소 넣기
1. 왼쪽 아래 **Project Settings → API Keys**(또는 Data API)에서 두 값을 복사
   - **Project URL**: `https://xxxx.supabase.co`
   - **Publishable key**(`sb_publishable_…`) 또는 **anon public** 키
2. 이 저장소의 [`config.js`](config.js)를 GitHub에서 열고 연필(✏️) → 두 값을 따옴표 안에 붙여넣기 → **Commit changes**
   (또는 두 값을 Claude에게 알려 주면 넣어 드립니다)
   - 이 키는 웹에 공개되는 용도라 올려도 됩니다. **service_role / secret 키는 절대 넣지 마세요.**
3. 1~2분 뒤 `https://airrotc29.github.io/minwon/` 새로고침 → 로그인 화면이 나오면 성공

### 5. 첫 로그인 후
- 이 기기에 예전 기록이 있으면 "서버로 옮길까요?"가 뜹니다 → **확인**(사진도 함께 옮겨집니다).
- **관리소장 계정**은 `supabase/schema.sql`의 「관리소장 계정 목록」(`app_managers`)에 적힌 이메일(`airrotc29@naver.com`)뿐입니다.
  - 이 계정만 지시·회신·재작업·삭제·직원 명단·설정을 할 수 있고, 다른 계정(직원 공용 계정 등)은 **접수, 진행·완료 보고, 사진 올리기만** 됩니다.
  - 화면에서 숨길 뿐 아니라 **데이터베이스가 직접 거부**하므로, 직원이 화면을 우회해도 관리소장 기능을 쓸 수 없습니다.
  - 소장님 계정을 바꾸거나 추가하려면 SQL Editor에서 `insert into public.app_managers(email) values ('새이메일');`을 실행하세요.
- `직원·설정`에서 직원 이름을 등록합니다. 개인 계정을 쓰는 직원은 **로그인 이메일**도 넣으면 로그인 때 자기 이름이 자동 선택됩니다(공용 계정이면 비워 두고, 직원이 '나는'에서 이름을 고릅니다).
- 직원에게는 주소(`https://airrotc29.github.io/minwon/`)와 아이디·비밀번호만 알려 주면 됩니다. 한 번 로그인하면 그 휴대폰에서는 유지됩니다.

### 알아 둘 점
- 다른 기기에서 바꾼 내용은 바로(실시간) 반영되고, 혹시 끊겨도 1분마다 새로 받아옵니다. 상단 `서버 연결됨` 표시를 누르면 바로 새로 고칩니다.
- 무료 요금제는 **7일 동안 아무도 접속하지 않으면 일시정지**됩니다. 매일 쓰면 문제없고, 멈췄다면 Supabase 대시보드에서 **Restore**를 누르면 됩니다.
- 무료 요금제는 자동 백업이 없으니 `직원·설정 → 백업 파일 받기`를 한 달에 한 번쯤 해 두세요.
- 퇴사한 직원은 **Authentication → Users**에서 계정을 지우면 바로 접속이 막힙니다.
- 민원인 이름·연락처는 받지 않고 동·호수만 기록합니다. 그래도 동·호수와 민원 내용으로 세대를 알아볼 수 있으니 계정 관리를 철저히 하세요(개인정보 보호법 제29조 안전조치의무).
- `config.js`가 비어 있으면 서버 없이 그 기기에만 저장하는 방식으로 동작합니다.
