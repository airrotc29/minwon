# 선민종합관리 민원관리 System

관리사무소 민원을 **접수 → 지시 → 보고 → 회신** 순서로 처리하는 웹 앱입니다.
화면은 GitHub Pages(`https://airrotc29.github.io/minwon/`)에서 열리고, 데이터는 **Supabase 서버 데이터베이스**에 저장되어
같은 주소로 접속해 로그인한 모든 사람·기기가 같은 내용을 봅니다. 아래 「서버 설정」을 한 번 해 주세요.

## 역할

| 역할 | 로그인 | 할 수 있는 일 |
|---|---|---|
| **본사 담당자** | 아이디(이메일)·비밀번호 | 모든 사업장 현황 한눈에 보기, 사업장 추가·보관, 관리소장 계정 만들기·비밀번호 재설정·삭제, 전체 사업장 월간 현황 인쇄, 아무 사업장에나 들어가 관리소장 기능 사용 |
| **임원** | 본사가 만들어 준 아이디·비밀번호 | 모든 사업장 열람만 — 본사 현황 그래프·숫자 팝업, 각 사업장 민원·처리 내역 보기, 월간 보고 인쇄. 접수·지시·회신·설정·계정 변경은 불가 |
| **관리소장** | 본사가 만들어 준 아이디·비밀번호 | 자기 사업장의 지시·회신·재작업·삭제·직원 명단·설정·월간 보고, **직원 접속 링크** 발급 |
| **직원** | **없음** — 관리소장이 보낸 접속 링크(QR)를 한 번 열면 끝 | 자기 사업장의 접수, 진행·완료 보고, 사진 올리기 |

서버(데이터베이스)가 같은 기준으로 다른 사업장의 기록을 아예 내려보내지 않습니다.

### 직원 접속 링크
- 관리소장이 **직원·설정 → 직원 접속 링크 → 만들기**를 누르면 긴 난수가 들어간 링크와 QR이 나옵니다. 직원은 휴대폰 카메라로 QR을 찍거나 카톡으로 받은 링크를 **처음 한 번만** 누르면 그 사업장 직원 화면이 열립니다('나는'에서 자기 이름만 고르면 됩니다).
- 열린 화면 위쪽의 **바탕화면에 아이콘 만들기** 안내대로(안드로이드: '앱으로 설치' 버튼 / 아이폰: 공유 → 홈 화면에 추가) 아이콘을 만들어 두면, 다음부터는 링크·QR 없이 아이콘만 눌러 들어옵니다. PC는 같은 링크를 브라우저에서 열고 즐겨찾기에 넣어 두면 됩니다.
- 직원이 그만두면 **링크 새로 만들기**를 누르세요. 예전 링크로 들어와 있던 휴대폰은 그 즉시 막히고, 남은 직원은 새 링크를 한 번 다시 열면 됩니다.
- 링크를 아는 사람은 누구나 그 사업장 직원 화면(접수·보고)을 쓸 수 있으니 단체방이 아니라 직원에게 개별로 보내세요.

## 사용 흐름

1. **접수 (관리소장 또는 직원)**: `+ 민원 접수`에서 동·호수, 분류, 긴급 여부, 내용을 입력합니다.
   - 직원이 접수하면 접수자 이름이 남고, 소장님 화면 **지시 대기**로 넘어갑니다.
   - 직원이 `내가 바로 처리`에 체크하면 소장 지시 없이 자기 담당으로 바로 처리하고 보고를 올립니다.
2. **지시 (관리소장)**: 담당 직원, 처리 기한, 지시 사항을 정해 보냅니다. 처리 중에는 `담당 변경 · 추가 지시`로 담당을 바꾸거나 지시를 더 보낼 수 있습니다.
3. **보고 (직원)**: 상단 `직원` 화면에서 자기 이름을 고르면 자기에게 온 지시만 보입니다. 여기서 `진행 보고`나 `완료 보고`를 올립니다.
4. **회신 (관리소장)**: 완료 보고가 오면 상단에 **회신 대기 N건**이 표시됩니다.
   - 민원인에게 보낼 안내 문구가 자동으로 만들어집니다. 휴대폰에서 노란 **카톡으로 보내기**를 누르면 공유창이 뜨고, 카카오톡에서 받을 방을 고르면 문구와 완료 사진이 함께 갑니다(문구는 복사도 되어 있어 글이 빠지면 붙여넣기). PC에서는 문구가 복사되니 PC 카톡에 붙여넣으면 됩니다.
   - 고친 뒤 `문구 복사`로 붙여 보내거나 인터폰·방문으로 알립니다.
   - 알린 방법(인터폰, 방문, 전화, 문자, 카톡, 안내문 부착)을 고르고 `회신완료로 기록`하면 **회신완료**로 바뀝니다.
   - 처리 중에도 `민원인에게 중간 안내`를 보낼 수 있고, 보고가 부족하면 `재작업 지시`로 다시 돌려보냅니다.

## 본사 화면 (본사 담당자 전용)

본사 담당자로 로그인하면 **본사 · 사업장 현황**이 먼저 열립니다.

- **숫자 타일**: 위쪽의 운영 사업장·이달 접수·미결·회신 대기·기한 초과 숫자를 누르면 그 자리에서 해당 민원 목록이 팝업으로 뜹니다. 줄을 누르면 그 사업장의 그 민원이 바로 열립니다.
- **그래프**: 사업장별 미결 현황(처리 단계별 누적 막대. 사업장 줄이나 색 조각을 누르면 해당 민원 목록 팝업), 최근 6개월 접수·처리 완료 추세 선 그래프, 선택한 달의 분류별 접수 비중 원형 그래프. 막대·점·조각에 마우스를 올리거나 손가락을 대면 값이 뜨고, **표로 보기**로 같은 숫자를 표로 볼 수 있습니다. 팝업에서 민원을 열었다가 뒤로 가기를 누르면 팝업 목록으로 돌아옵니다.
- **돌아오기**: 휴대폰·브라우저의 뒤로 가기 버튼을 누르면 본사 현황으로 돌아옵니다. 사업장에 들어가면 화면 위에 남색 띠가 생기고, 거기의 사업장 선택 칸에서 다른 사업장이나 **← 본사 현황 (전체)**를 고를 수 있습니다.
- **사업장별 현황표**: 미결, 지시 대기, 회신 대기, 기한 초과, 긴급, 이달 접수·완료, 직원 수, 최근 변동. 숫자가 있으면 빨갛게 표시됩니다. 줄을 누르면 그 사업장 화면으로 들어가 관리소장과 똑같이 지시·회신·설정·월간 보고를 할 수 있고, 상단의 사업장 선택 칸으로 바로 옮겨 다닐 수 있습니다. **본사 현황** 버튼으로 돌아옵니다.
- **전체 사업장 월간 현황**: 보고 월을 고르면 사업장별 이월·접수·긴급·처리 완료·처리율·평균 기간·월말 미결과 합계가 나오고, **인쇄 / PDF 저장**으로 결재란(담당·팀장·대표)이 있는 A4 보고서를 만듭니다. 모든 쪽 하단 중앙에 선민종합관리(주) 상표가 찍힙니다.
- **사업장 관리**: 사업장 추가, 이름 변경, 보관(계약 종료 등 — 현황에서 빠지지만 기록은 남고 되돌릴 수 있음).
- **계정 관리**: 관리소장 계정을 앱에서 바로 만듭니다 — 아이디(이메일 형식, 실제 메일은 안 보냄), 비밀번호(6자 이상), 역할(관리소장/본사 담당자), 사업장, 이름 → **계정 만들기 / 지정**. 만든 아이디·비밀번호를 소장에게 알려 주면 됩니다. 목록에서 **비밀번호 재설정**, **삭제**도 됩니다. 직원 계정은 필요 없습니다(직원 접속 링크 사용).

## 휴대폰에서

- 민원을 고르거나 접수·설정·보고 화면을 열면 전체 화면으로 뜹니다. **← 목록으로** 버튼이나 휴대폰 뒤로 가기로 닫습니다.
- **+ 민원 접수** 버튼은 화면 오른쪽 아래에 떠 있습니다.
- 본사 화면의 넓은 표는 옆으로 밀어 보고, 숫자 팝업은 카드 목록으로 보입니다.

## 지시 대상 여러 명

- 지시할 때 담당 직원을 **여러 명 선택**할 수 있습니다(이름 칸을 눌러 체크). 지시를 받은 직원 각자의 화면에 그 민원이 보이고, 각자 진행·완료 보고를 올립니다.
- 모든 담당자가 **완료 보고**를 올려야 민원이 ‘처리완료(회신 대기)’가 됩니다. 그 전에는 ‘처리중’으로 남고, 지시 사항 옆에 완료 보고 `1/2`처럼 표시됩니다.
- 직원 화면에서 내가 접수한 민원은 **지시 대기**로 따로 세지 않습니다(전체 목록에서 볼 수 있음). 소장 화면에만 지시 대기 숫자가 나옵니다.

## 새 민원 소리 알림

- 다른 사람이 새 민원을 접수하면 소장·직원 모두의 휴대폰에서 **종소리(미·솔·도 두 번)와 진동**이 울리고, 화면 위에 빨간 **새 민원 접수** 띠가 뜹니다. **확인**을 누르면 그 민원이 열립니다. 내가 접수한 민원은 울리지 않습니다.
- 소장·직원은 항상 켜져 있고(따로 켜고 끄는 버튼은 없습니다), 소리는 브라우저 규칙상 화면을 한 번 건드린 뒤부터 납니다(앱을 연 뒤 아무 곳이나 한 번 누르면 됩니다).
- 앱을 열어 둔 동안(화면이 켜져 있거나 다른 탭에 있을 때)만 울립니다. 앱을 완전히 닫았거나 잠금 화면에서는 울리지 않습니다. 그때까지 울리게 하려면 서버에서 푸시 알림을 따로 보내야 합니다.
- 본사 담당자·임원에게는 울리지 않습니다.

## 뒤로 가기

- 화면이 바뀔 때마다(민원 선택, 접수·설정·보고 열기, 역할 전환, 본사↔사업장, 팝업) 브라우저 기록이 한 칸 쌓입니다. 휴대폰·브라우저의 뒤로 가기는 항상 직전 화면으로 돌아갑니다.
- 첫 화면에서 뒤로 가기를 누르면 「앱에서 나가시겠습니까?」를 묻고, 확인을 눌러야 나갑니다.

## 월간 보고서 (관리소장 전용)

상단 **월간 보고** 버튼(관리소장 계정에만 보임)에서 관리단에 올리는 월간 민원 처리 보고서를 만듭니다.

- **보고 월**을 고르면 자동 집계: 이달 접수, 이달 처리 완료(민원인 회신까지), 처리율, 평균 처리 기간, 월말 미결, 긴급 민원, 처리 기한 준수율, 전월 이월 미결
- 분류별·동별(상위 10)·담당자별 표, 이달 접수 민원 목록(처리 내용 포함), 전월 이월 미결 목록
- **특이사항·관리소장 의견**, **다음 달 계획**을 적고 **의견 저장**(서버에 달별로 저장, 관리소장만 저장 가능)
- **인쇄 / PDF 저장**: A4 한 장 형식(결재란: 담당·관리소장·관리단)으로 인쇄하거나, 인쇄 창에서 'PDF로 저장'을 골라 파일로 보냅니다.
- **엑셀(CSV) 받기**: 그 달 접수 민원 전체를 엑셀에서 열 수 있는 파일로 받습니다.
- 수신(관리단 이름)·발신은 보고서 화면에서 고치면 다음 달에도 그대로 쓰입니다.

## 사진

- 접수할 때와 직원이 진행·완료 보고를 올릴 때 **＋ 사진**으로 사진을 붙입니다(한 번에 6장까지). 휴대폰에서는 바로 촬영하거나 앨범에서 고를 수 있습니다.
- 휴대폰 사진은 올리기 전에 자동으로 줄입니다(긴 변 1280px, 장당 약 150KB).
- 처리 내역에 작은 사진으로 보이고, 누르면 크게 보거나 저장할 수 있습니다.
- 사진은 Supabase의 비공개 사진 저장소(`photos`)에 저장되고, 로그인한 사람만 볼 수 있습니다.
- 백업 파일(json)에는 사진이 들어가지 않습니다.

### 사진 용량
Supabase 무료 요금제의 사진 저장 한도는 **1GB(약 6,800장)** 입니다.

| 하루 사진 수 | 무료 1GB로 버티는 기간 |
|---|---|
| 10장 | 약 1년 10개월 |
| 30장 | 약 7~8개월 |
| 50장 | 약 4~5개월 |

- `직원·설정 → 서버`에 사진 장수와 사용량(어림값)이 보이고, 80%를 넘으면 소장님 화면 위쪽에 안내가 뜹니다. 정확한 값은 Supabase 대시보드 → Storage에서 봅니다.
- 한도가 차면 **Pro 요금제(월 25달러)** 로 올리면 사진 저장이 100GB(하루 30장 기준 수십 년)로 늘고, 매일 자동 백업과 일시정지 없음이 함께 따라옵니다.

## 로고

- 선민종합관리(주) 로고(남색 SM 마크)가 상단·브라우저 탭·홈 화면 아이콘에 들어가 있고(`logo.svg`), 로그인 화면 위에는 회사 카드(SM · FACILITY MANAGEMENT · 선민종합관리(주) · 사람을 먼저 생각하는 관리 · 신뢰로 완성하는 가치), 화면 맨 아래에는 회사 이름 줄이 보입니다.
- 또는 앱의 `직원·설정 → 로고 이미지 올리기`로 그 기기에만 로고를 넣을 수 있습니다.
- 로고가 없으면 초록색 "선민" 글자 마크가 대신 보입니다.

## 서버 설정 (Supabase) — 처음 한 번

### 1. 가입하고 프로젝트 만들기
1. https://supabase.com 접속 → **Start your project** → **Continue with GitHub**(지금 GitHub 계정으로 가입).
2. **New project**
   - Organization: 처음 만들 때 이름 아무거나, 요금제 **Free**
   - Project name: `minwon`
   - Database Password: **Generate a password** 누르고 따로 적어 두기(앱에서는 안 씀)
   - Region: **Northeast Asia (Seoul)** — 데이터가 국내에 저장되도록(개인정보 국외 이전 문제 예방)
   - **Create new project** → 1~2분 기다리기

### 2. 데이터베이스 만들기 (복사·붙여넣기 한 번)
1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 저장소의 [`supabase/schema.sql`](supabase/schema.sql) 내용을 전부 복사해 붙여넣고 **Run**
3. 아래에 `Success. No rows returned`가 나오면 끝(민원·처리내역·직원·설정 표, 관리소장/직원 권한 규칙, 실시간 반영, 사진 저장소가 한 번에 만들어집니다)
   - "destructive operation" 경고가 뜨면 **Run query**. 표를 지우는 명령은 없어서 여러 번 실행해도 데이터는 그대로입니다.
   - 앱이 새 버전으로 바뀌면서 이 파일이 바뀌었을 때도 같은 방법으로 다시 실행하면 됩니다.

### 3. 로그인 계정 만들기
1. 왼쪽 **Authentication** → **Sign In / Providers**(또는 Providers) → **Email**이 켜져 있는지 확인
3. **Authentication → Users → Add user → Create new user**로 **본사 담당자 계정 하나**만 만듭니다(이메일, 비밀번호, **Auto Confirm User** 체크). `supabase/schema.sql`에 적힌 이메일(`boss-hq@sunmin.kr`, `airrotc29@naver.com`)이 자동으로 본사 담당자가 됩니다. 본사 계정을 바꾸려면 앱의 **본사 → 계정 관리**에서 역할을 본사 담당자로 하여 새 계정을 만들고, 그 계정으로 로그인한 뒤 예전 계정을 삭제하면 됩니다(비밀번호는 6자 이상).
   - 관리소장 계정은 나중에 앱 **본사 → 계정 관리**에서 만들고, 직원은 계정이 필요 없습니다.
4. **Authentication → Sign In / Providers**에서 세 가지를 맞춥니다.
   - **Anonymous sign-ins**: **ON** (직원이 링크만으로 들어오기 위해)
   - **Allow new users to sign up**: **ON** (본사가 앱에서 관리소장 계정을 만들기 위해)
   - **Email → Confirm email**: **OFF** (만든 계정이 바로 로그인되도록)
   - 가입이 열려 있어도 역할이 지정되지 않은 계정은 아무것도 볼 수 없으므로 기록은 보호됩니다.

### 4. 앱에 서버 주소 넣기

   - **Project URL**: `https://xxxx.supabase.co`
   - **Publishable key**(`sb_publishable_…`) 또는 **anon public** 키
2. 이 저장소의 [`config.js`](config.js)를 GitHub에서 열고 연필(✏️) → 두 값을 따옴표 안에 붙여넣기 → **Commit changes**
   (또는 두 값을 Claude에게 알려 주면 넣어 드립니다)
   - 이 키는 웹에 공개되는 용도라 올려도 됩니다. **service_role / secret 키는 절대 넣지 마세요.**
3. 1~2분 뒤 `https://airrotc29.github.io/minwon/` 새로고침 → 로그인 화면이 나오면 성공

### 5. 첫 로그인 후
- 이 기기에 예전 기록이 있으면 "서버로 옮길까요?"가 뜹니다 → **확인**(사진도 함께 옮겨집니다).
- **역할 지정**: 본사 담당자(`boss-hq@sunmin.kr`)로 로그인해 **본사 → 사업장 관리**에서 사업장을 만들고, **계정 관리**에서 각 계정의 역할과 사업장을 지정합니다. 예전 버전에서 올린 경우 기존 기록은 '기본 사업장(main)'에 있고, 이미 있던 로그인 계정은 그 사업장의 직원으로 자동 지정되어 있으니 필요하면 역할만 바꾸면 됩니다.
  - 화면에서 숨길 뿐 아니라 **데이터베이스가 직접 거부**하므로, 다른 사업장 기록은 볼 수도 고칠 수도 없습니다.
- `직원·설정`에서 직원 이름을 등록합니다. 개인 계정을 쓰는 직원은 **로그인 이메일**도 넣으면 로그인 때 자기 이름이 자동 선택됩니다(공용 계정이면 비워 두고, 직원이 '나는'에서 이름을 고릅니다).
- 직원에게는 주소(`https://airrotc29.github.io/minwon/`)와 아이디·비밀번호만 알려 주면 됩니다. 한 번 로그인하면 그 휴대폰에서는 유지됩니다.

### 알아 둘 점
- 다른 기기에서 바꾼 내용은 바로(실시간) 반영되고, 혹시 끊겨도 1분마다 새로 받아옵니다. 상단 `서버 연결됨` 표시를 누르면 바로 새로 고칩니다.
- 무료 요금제는 **7일 동안 아무도 접속하지 않으면 일시정지**됩니다. 매일 쓰면 문제없고, 멈췄다면 Supabase 대시보드에서 **Restore**를 누르면 됩니다.
- 무료 요금제는 자동 백업이 없으니 `직원·설정 → 데이터 백업 → 엑셀 파일로 백업받기`를 한 달에 한 번쯤 해 두세요. 엑셀 파일에는 민원·처리내역·직원 시트가 들어 있어 나중에 열어 보고 인쇄하기 좋습니다. 서버에 다시 넣을 일을 대비하려면 「복원용 파일 받기(.json)」도 함께 받아 두고, 내용은 「복원용 파일 열어보기」로 확인할 수 있습니다.
- 퇴사한 직원은 관리소장이 **직원 접속 링크 → 링크 새로 만들기**를 누르면 바로 막힙니다. 퇴사한 소장은 본사가 **계정 관리 → 삭제**합니다.
- 민원인 이름·연락처는 받지 않고 동·호수만 기록합니다. 그래도 동·호수와 민원 내용으로 세대를 알아볼 수 있으니 계정 관리를 철저히 하세요(개인정보 보호법 제29조 안전조치의무).
- `config.js`가 비어 있으면 서버 없이 그 기기에만 저장하는 방식으로 동작합니다.
